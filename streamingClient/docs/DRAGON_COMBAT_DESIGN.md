# 猪大 VS 恶龙：战斗规则草案

状态：2026-10-18 设计提案，尚未修改当前 v2.2.1 的战斗程序，也未发布插件。

## 基本循环

- 一场对局双方各从 1000 生命开始，规则完全对称。
- 每轮备战时攻击、防御、速度从 0 / 0 / 0 开始，靠本轮礼物增加，不保留上一轮属性。
- 生命跨轮保留，直到一方生命归零；下一场才恢复到 1000。否则每轮恢复生命会使未能一击击杀的投入失去意义。
- 第一版建议仅开放攻击、防御、速度礼物；生命暂时固定，避免加血与防御叠加拖延对局。这是提案，现有加血事件尚未移除。
- 备战结束锁定双方属性，再结算交锋。交锋动画期间的新礼物进入下一轮，不改变已锁定的结果。
- 双方都没有攻击时，不会凭空造成伤害；纯速度没有输出，纯防御也无法反震。

## 三项属性

### 攻击：主动伤害和反击上限

一次普通攻击的原始伤害等于攻击值。攻击值同时限制防守反击的伤害，让防守方仍有理由投入攻击。

### 防御：减伤与格挡反击

每次受到普通攻击，防御抵挡等量伤害，但最多抵挡本次原始伤害的 70%。防守方立即反击所抵挡伤害的 50%，反击伤害最多等于防守方自己的攻击值。

反击随本次受击一起结算，不要求速度领先；即使本次受击致死，已经产生的反击仍结算，因此可能同归于尽。反击不再次触发格挡、减伤或反击，避免无限递归。

防御能同时减少己方损失、增加对手损失，因此可以制衡纯攻击；70% 的格挡上限避免无限堆防形成完全免伤。反击上限绑定攻击，避免纯防御成为自动获胜方案。

### 速度：先手与按差值破防

速度较高的一方先攻击。先手攻击每领先 1 点速度，暂时忽略对手 2 点防御，最多忽略对手防御的 75%。只影响这一次先手攻击，不降低对手面板属性。

先手攻击及其格挡反击结算后，若双方都存活，后手方再进行一次普通攻击。后手攻击不获得破防。双方速度相同则同时攻击，不偏向猪大或恶龙。

速度只决定顺序时，对非致死交锋没有收益，容易变成快结束才补 1 点。按速度差逐点破防能使速度在防御对局中持续有用，也避免只领先 1 点就获得整份固定奖励。

## 精确计算

所有输入均为非负整数。设进攻方攻击为 A，防守方防御为 D、攻击为 AD，双方速度差为 ΔS。

```text
普通攻击有效防御 = D
先手攻击有效防御 = max(D × 25%, D − 2 × ΔS)，其中 ΔS > 0

格挡量 = floor(min(A × 70%, 有效防御))
直接伤害 = A − 格挡量
反击伤害 = floor(min(格挡量 × 50%, AD))
```

同一次攻击的直接伤害与反击伤害同时扣除，再判断存活。速度相同时，双方从同一个交锋快照分别计算各自的直接伤害、反击伤害，合并扣除后才判胜负。不会因先处理某个阵营而取消另一方已经发生的攻击。

生命只扣到 0；只有一方存活则该方获胜，双方都归零则平局。所有格挡、破防、反击系数均为第一版候选值，后续应通过真实礼物配点记录调整。

## 相同投入的具体例子

以下每轮都给双方各 1000 点预算，连续各轮重复相同配点；双方初始生命均为 1000。列中的顺序都是攻击 / 防御 / 速度。

| 对局         | 配点                           | 结果                           |
| ------------ | ------------------------------ | ------------------------------ |
| 强攻 vs 守反 | 1000 / 0 / 0 vs 300 / 700 / 0  | 守反第 2 轮获胜，剩余 400 生命 |
| 守反 vs 快攻 | 300 / 700 / 0 vs 700 / 0 / 300 | 快攻第 2 轮获胜，剩余 526 生命 |
| 快攻 vs 强攻 | 700 / 0 / 300 vs 1000 / 0 / 0  | 强攻第 1 轮获胜，剩余 300 生命 |

守反对强攻的第一轮：强攻打出 1000，守反挡下 700、损失 300，反击伤害受自身攻击限制为 300；加上守反自己的普通攻击 300，强攻共损失 600。

快攻对守反的第一轮：速度领先 300，忽略防御受到 75% 上限限制，守反的有效防御为 175；快攻造成 525 伤害，自身受到 87 点反击，再受到存活后手的普通攻击 300。

这三个例子说明配点可以相互制衡，不代表任何预算和生命阶段都保持同一胜负关系。生命接近斩杀线时，先手自然更重要。

## 初步数值检查及限制

本机草案模型枚举总预算 100、300、600、1000、1500、3000，各档以预算的 10% 为一步分配三项属性，每档 66 种配点互相比试，共 26136 场有方向的对局，含自身配点对局。

在这个有限网格中，没有一种配点对所有其他配点均保持不败；全攻击也不是任一预算档胜场最多的配法。这只是初步排除明显通吃方案，不能视为实战平衡验证。模型与结果保存于 `.local/dragon-combat-design/`。

模拟假设双方每轮投入相等、配点不变，不包含观众临场补点、网络延迟、礼物价值差或不同剩余生命的完整策略搜索。固定 1000 生命下，高预算更容易触发先手斩杀，正式版还需要覆盖高额投入和濒死局的实测。

礼物平衡必须按价值换算，不能只比较件数。相同价值的礼物应先形成可比的属性点预算；不能让某类同价礼物天然获得数倍点数。主播改变映射增量后，也会改变规则平衡，测试应使用实际上线的映射。

## 后续实现要求

- 更换现有“恶龙先攻、猪大满足条件才回击”的非对称规则；删除本规则的 40% 属性保留机制。
- 基础生命默认 1000，三项属性默认 0；参数校验必须允许 0，旧场景的规则迁移不能静默沿用旧数值。
- 宿主统一计算结果并保存交锋快照；桌面、场景输出、手机仅消费同一结果，不能由各自播放进度决定胜负。
- 交锋截止线及礼物归属必须原子化；动画期间的下一轮礼物不能被属性清零覆盖。
- 正常展示用先手攻击、受击格挡反击、后手攻击等镜头表达规则；不需要在直播画面重新堆放规则文字。
- 对局结束播放短暂胜负特效后应能继续接收下一场礼物，不要求主播反复启用插件。下一场礼物须单独排队，不丢失、不影响本场已确定结果；自动开局节奏属于后续实现范围。
- 若发生同归于尽，应明确显示平局结果；不能靠固定阵营优先级决定赢家。
- 现有影片仍保留静态构图确认流程，本草案不发起影片制作。
