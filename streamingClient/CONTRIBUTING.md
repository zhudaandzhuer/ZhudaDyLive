# 贡献指南

感谢参与猪大直播工作台。系统界面和项目文档统一使用简体中文；代码标识符使用英文。

## 本机流程

1. 使用 Node.js 24+，执行 `npm ci`。
2. 按 [开发说明](docs/DEVELOPMENT.md) 启动隔离的本机服务和客户端。
3. 提交前执行 `npm run check` 与 `npm run build`。
4. 需要窗口或音频行为时，再运行相关 Electron 验收并注明实际平台。

不要用自己的生产数据库、Cookie 或正在直播的场景做测试。测试密钥在测试时随机生成；`tests/fixtures.ts` 不包含生产密钥。运行产物与维护记录放在 `.local/`。

## 修改边界

- 新玩法优先作为 `../plugins/` 下的插件实现，复用宿主提供的事件、礼物、热键、音频和参数接口。
- 改动 IPC、manifest 或存储结构时，先更新 `packages/contracts/`，再更新宿主与测试。
- 宿主拥有权威状态。编辑器、输出和手机页面只渲染，不能重复结算礼物。
- 插件版本不可覆盖；修改已发布插件内容时增加版本，说明旧场景如何应用更新。
- 原始封包、身份信息及本机目录不要进入 issue、日志附件或提交。
- 修改行为应配有能证明结果的测试；只改文案和样式时，使用现有检查及必要的目视验证。

## 提交与 PR

一个 PR 聚焦一个问题，说明触发方式、最终行为和验证结果。窗口、动画或插件界面改动可附脱敏截图。报告未测试的平台与已知限制，不将模拟检查描述为真机验收。

建议使用 `fix:`、`feat:`、`docs:`、`refactor:` 或 `test:` 开头的提交信息。维护者可能要求拆分大型变更或补充复现步骤。

提交贡献表示你有权提供这些内容，并同意按项目 MIT 许可证发布；第三方内容必须保留来源与许可。详细资料见 [文档索引](docs/README.md)。
